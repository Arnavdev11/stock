# Responsive redesign (English only) — review notes

Branch `feat/responsive-redesign-rebuild`, based on `main` at `66fe34a`. This is a **reconstruction** of the planned
responsive work from the agreed specification. It is not, and does not claim to be, the lost branch
`feat/responsive-layout-pr1` / `c2658f0`. Nothing here changes data, data files, workflows, updaters, schemas or calculations.

## What changed

| Area | Change |
|---|---|
| Top bar | Page and bar 1200px wide. Full link row only from a 1150px bar, so the links never wrap inside the bar (the old 1001–1005px wrap). The desktop search keeps a 15.5rem basis, so its placeholder is no longer cut off at 1280px and wider. Tablet (600–1149px): brand, search and menu button on one row. Phone: search on its own row. |
| Colours | Gain/loss colours `#0B7A50` / `#C23333` pass WCAG AA on white and on the page background (previously 3.79:1 and 4.40:1). Dark mode: selected tabs, chips, nav items and buttons use dark text on the accent (white was 2.57:1). |
| Touch targets | 24px minimum everywhere (WCAG 2.5.8); 44px for tabs, selects, buttons, the menu button and the search input at compact widths. |
| Fundamental screen | Filter panel first: P/E min/max and "Which P/E", P/B min/max, ROE at least (existing `#roe`, choices and 15% default kept), Sector. Results count, Clear filters, `aria-sort`. The other two screen tabs follow the same rules. |
| Strict numbers | A stored value passes an active numeric filter only if it is a finite JSON number. Missing, blank, dash, text and non-finite values never pass. A typed value must be a plain number of 0 or more; otherwise the box is marked invalid, the message is announced and no rows are shown. |
| Negative P/E | Excluded from any P/E range and from "Positive only"; listed only with "Negative only (loss-making)". When sorting by P/E, zero and negative P/E come after every positive P/E in both directions. The data is unchanged. |
| Home page | The All-Time High / Low and Sector Leaders / Laggards sections, and the Trending "All-Time High / Low" tab button, are removed. Their renderers, data and the Stage 8C pinned code are untouched. |
| Mobile tables | Below 640px the screen tables become cards. Every field keeps its column name, the numbers sit in a compact grid, the column buttons become sort chips and the tabs wrap. |
| Stock page | Wider page and the touch-target fixes only. **The two-column layout is not done: see the blocker below.** |

## Protections

* Every `index.html` edit is recorded in `tests/approved_page_edits.json` as `decision_edits`, generated by
  `tests/page_edit_manifest.py`. Each entry is the exact new text and the exact text it replaced in `66fe34a`.
  The existing guards (`guard_update_yml.without_coverage_fixes`, `tests/legacy_5i.js`) reverse these edits first, so every
  older byte-identity pin still runs unchanged and still detects any *other* change. `test_responsive_redesign.py`
  keeps the record exact and confirms that pages from before the redesign come back unchanged.
* The Phase 2B script pin in `tests/test_technicals.js` keeps its **original** hash. It is now checked after reversing
  exactly the recorded edits, so any further change to that block still fails.
* The search-module SHA pin (`tests/search_module_pin.json`) was not touched, because the search module was not edited.
* Spec tests that described the old layout were updated to describe the new one, keeping their constraints:
  `tests/test_global_navigation.js` (breakpoints) and `tests/test_market_dashboard_ui.js` (13 sections, with the two removed sections
  now asserted absent).

## Blocker: two-column stock-detail layout (not implemented)

The Stock Detail script writes `#detail` as one flat list. Each heading (`<h3>Overview</h3>`, `Financial Health`,
`Cash Flow`, `Price chart`) is a **sibling** of its tiles and notes, not their parent. Seven modules then depend on that flat structure:

| Module | Dependency |
|---|---|
| Stock Research (Phase 4 Step 1) | places `#detailResearch` only if its parent is `#detail` (`node.parentNode===box`) |
| Investment Checklist (Phase 4 Step 2) | same check for `#detailChecklist`, and needs `Stock Research</h3>` in `#detail` |
| Financial History (Phase 4 Step 4E) | same check; inserts after the research section (`r.nextSibling`) |
| `stocklens-snapshot` | same check; inserts before the Overview heading |
| `stocklens-shareholding` | same check; inserts after Financial History |
| `stocklens-quarterly` | same check; inserts next to its anchor |
| `stocklens-nav` | finds section headings only as **direct children** of `#detail` (`h[i].parentNode===box`) for the section links and scrolling |

A genuine two-column layout needs headings grouped with their content. Doing that with CSS grid on the flat list would
separate headings from their content, which you ruled out. Wrapping groups in containers would break all seven checks above.

**Minimal proposed change (needs your approval):**
1. The Stock Detail renderer wraps each heading and its content in `<section class="sd-group" id="detailOverview|…">`.
2. The six placement checks accept a node whose closest `#detail > *` ancestor is in `#detail`, and anchor on the group instead of the heading.
3. `stocklens-nav` looks for `#detail > .sd-group > h3` as well as `#detail > h3`.
4. Then a CSS grid on `#detail` places whole groups in two columns on desktop, two narrower columns on tablet, and source order on mobile.

This touches the Stock Detail script and six pinned modules, so it needs approved edits for each, updated nav and placement tests,
and browser checks of section links, Back/Forward and the live panel. Risk: placement races (modules re-insert on every render) and section scrolling.

## Not verified / limitations

* Only synthetic data was used (`tests/synthetic_site.py`; invented values, marked synthetic). No real-data validation.
* The price chart was not rendered: its library loads from unpkg, which this environment blocks, so the page showed its
  "Chart library could not be loaded" fallback. Charts, Financial History, Shareholding, Quarterly Results, Research
  and the comparison page remain **unverified with populated data**.
* Manrope (Google Fonts) was blocked; the checks used the fallback font (Inter, which has similar metrics). The search box's minimum
  size includes headroom for this.
* Headless Chromium only. No Safari, Firefox or real-device checks.
* Sector: the updater publishes `sector` only for the ten test symbols until the sector approval gate opens, so with real data the
  Sector filter will offer few sectors. The panel says how many stocks have one.
* P/B range: a negative P/B (negative equity) is treated as a plain number and can pass a P/B maximum. Only the P/E rule was specified;
  tell me if P/B should follow it.
* No pagination: all matching stocks are listed. With about 500 stocks the phone list will be long.
